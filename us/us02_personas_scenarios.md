# US02 - Définir les personas et leurs scénarios d'usage

## Description
Identification et formalisation des profils utilisateurs types (Étudiants, Enseignants, Professionnels) et de leurs parcours sur la plateforme ReviewMe.

---

**EN TANT QU'** Équipe projet  
**JE VEUX** formaliser les personas prioritaires et les scénarios concrets qui justifient le produit  
**AFIN DE** relier les futures fonctionnalités à des besoins réalistes et défendables.

---

## Critères d'acceptation

- [x] **Diversité des Profils** : Au moins 3 personas sont décrits avec objectifs, frustrations et contexte.
- [x] **Scénarisation** : Chaque persona est relié à au moins 1 scénario d'usage prioritaire.
- [x] **Couverture des besoins** : Les scénarios couvrent au moins un besoin principal et un besoin secondaire.
- [x] **Cohérence** : Les personas sont cohérents avec le domaine de l'éducation et de l'entreprise.

---

## Persona 1 : Lucas (Étudiant / Apprenti)

### 1. Critères sociodémographiques
| Critère | Détails |
| :--- | :--- |
| **Prénom / Profil** | Lucas, Étudiant en Master 1 Informatique (ou Apprenti Développeur). |
| **Âge** | 22 - 25 ans. |
| **Localisation** | Cergy-le-Haut / Port Cergy (Zone Cergy-Pontoise, Île-de-France). |
| **Situation pro** | Étudiant en alternance dans une ESN ou une startup à Cergy ou La Défense. |
| **Niveau d'études** | Bac +4 / Bac +5 en ingénierie logicielle. |
| **Revenus** | 1 100 € - 1 600 € (Salaire d'apprenti ou gratification de stage). |
| **Technologies** | JavaScript (React/Node.js), Dart (Flutter), Python. |

### 2. Description du Persona
Lucas est un jeune développeur passionné qui sait produire un code fonctionnel mais souffre du "syndrome de l'imposteur technique". Il s'inquiète de la qualité de sa structure, de sa dette technique et de la lisibilité de son code. Il cherche une confrontation d'idées pour élever son niveau architectural et maximiser son employabilité.

### 3. Psychographie
| Attribut | Analyse |
| :--- | :--- |
| **Motivations** | Atteindre l'excellence technique ; comprendre les Design Patterns ; validation par des pairs. |
| **Aspirations** | Devenir Lead Developer ou CTO d'ici 5 à 7 ans. |
| **Valeurs** | Partage de connaissances ; pragmatisme ; critique constructive ; Kaizen. |
| **Craintes** | Développer de mauvaises habitudes ; être jugé sur la médiocrité de sa logique interne. |
| **Intérêts** | Veille techno (Medium, Dev.to) ; Meetups ; Gaming compétitif. |

### 4. Comportements d'achat
| Vecteur | Description |
| :--- | :--- |
| **Canaux** | GitHub ; Discord ; Reddit ; LinkedIn. |
| **Décision** | Rapidité du feedback ; légitimité des relecteurs ; simplicité de l'UI. |
| **Habitudes** | Adepte du "Freemium" ; prêt à payer un abonnement modeste pour sa carrière. |
| **Prix** | Sensibilité haute (budget étudiant), mais perçu comme un investissement. |
| **Influenceurs** | Professeurs à CY Tech ; Micode, Grafikart. |

### 5. Problématiques clés
1. **Stagnation qualitative** : "Comment savoir si ma logique est optimale si mon code tourne déjà ?"
2. **Isolement** : "Où trouver un regard critique bienveillant hors projets de groupe ?"
3. **Transition pro** : "Quels standards d'experts je ne maîtrise pas encore ?"
4. **Multiplicité des approches** : "Existe-t-il une manière plus élégante d'écrire cette fonction ?"
5. **Déficit de mentoring** : "Comment obtenir des conseils d'architecte sans être en grande entreprise ?"

### 6. Arguments clés
- **Accélérateur de carrière** : Gagnez deux ans d'expérience via la pensée senior.
- **Culture Clean Architecture** : Apprenez à produire un code qui dure.
- **Environnement Safe** : Critique centrée sur la logique, pas sur l'échec.
- **Networking local** : Connectez-vous avec les talents de l'axe Cergy-Paris.
- **Visualisation pro** : Suivez l'évolution de votre maturité technique.

### 7. Scénario d'usage prioritaire : "La quête de la Clean Architecture"
*   **Besoin Principal** : Valider que la structure de son projet Flutter ne deviendra pas un "plat de spaghettis" dans 3 mois.
*   **Besoin Secondaire** : Rencontrer un développeur senior de la région pour une potentielle alternance.
*   **Déroulement** : Lucas poste un lien vers son repo GitHub. Il pose la question : *"J'ai tenté d'isoler la logique métier dans mes services, qu'en pensez-vous ?"*. Il reçoit 2 retours d'experts dont Marc, ce qui lance une discussion passionnante.

## Persona 2 : Sarah (Enseignante / Professeure)

### 1. Critères sociodémographiques
| Critère | Détails |
| :--- | :--- |
| **Prénom / Profil** | Sarah, Professeure agrégée d'informatique. |
| **Âge** | 40 - 50 ans. |
| **Localisation** | Cergy (CY Tech ou Université de Cergy-Pontoise). |
| **Situation pro** | Responsable de module de programmation / Projets de fin d'études. |
| **Niveau d'études** | Doctorat en Sciences de l'Information. |
| **Revenus** | 3 500 € - 4 500 €. |
| **Technologies** | C++, Java, Algorithmique fondamentale. |

### 2. Description du Persona
Sarah cherche à moderniser ses méthodes d'évaluation. Elle est frustrée par le temps passé à corriger des erreurs de structure basiques et aimerait que ses étudiants développent un esprit critique sur leur propre code. Elle voit en ReviewMe un outil pédagogique complémentaire pour favoriser le peer-learning.

### 3. Psychographie
| Attribut | Analyse |
| :--- | :--- |
| **Motivations** | Réussite pédagogique ; autonomie des étudiants ; mise à jour des pratiques. |
| **Aspirations** | Améliorer le taux d'insertion professionnelle de ses élèves. |
| **Valeurs** | Rigueur ; pédagogie active ; transmission ; excellence académique. |
| **Craintes** | Déconnexion avec les réalités du marché ; surcharge de travail liée aux corrections. |
| **Intérêts** | Recherche académique ; éducation numérique ; randonnée. |

### 4. Comportements d'achat
| Vecteur | Description |
| :--- | :--- |
| **Canaux** | Publications académiques ; conférences (LUDOVIA) ; réseau interne établissement. |
| **Décision** | Intégration pédagogique ; respect des données (RGPD) ; facilité de suivi. |
| **Habitudes** | Institutionnelle (budget école) ou licences groupées. |
| **Prix** | Sensibilité basse si justifié par un budget d'équipement pédagogique. |
| **Influenceurs** | Inspection générale ; pairs universitaires ; éditeurs de solutions EdTech. |

### 5. Problématiques clés
1. **Évaluation à l'échelle** : "Comment offrir un feedback qualitatif à 100 étudiants simultanément ?"
2. **Engagement** : "Comment inciter les étudiants à lire et critiquer le code de leurs pairs ?"
3. **Actualisation** : "Comment garantir que les conseils donnés sont alignés avec les pratiques actuelles ?"
4. **Temps de correction** : "Comment réduire le temps passé sur les erreurs de forme pour me concentrer sur la logique ?"
5. **Traces d'apprentissage** : "Comment visualiser la progression de la maturité technique d'un élève sur l'année ?"

### 6. Arguments clés
- **Levier de Peer-Learning** : Transformez la classe en une communauté de micro-mentors.
- **Gain de productivité** : Automatisez la revue réflexive pour vous concentrer sur les concepts complexes.
- **Tableau de bord pédagogique** : Visualisez d'un coup d'œil les forces et faiblesses techniques de votre promotion.
- **Standardisation pro** : Préparez vos étudiants aux processus de Code Review des meilleures entreprises.
- **Ressources mutualisées** : Créez une bibliothèque de cas d'usage réels pour vos cours.

### 7. Scénario d'usage prioritaire : "Le TD inversé"
*   **Besoin Principal** : Faire en sorte que ses 40 étudiants de Cergy relisent mutuellement leur code avant le rendu final.
*   **Besoin Secondaire** : Identifier les erreurs de logique récurrentes pour adapter son prochain cours magistral.
*   **Déroulement** : Sarah crée un groupe privé pour sa promotion. Elle demande aux élèves de poster leur TP et de commenter au moins 2 autres projets. Elle observe via son dashboard qui a le regard le plus affûté.

## Persona 3 : Marc (Senior Developer / Lead Tech)

### 1. Critères sociodémographiques
| Critère | Détails |
| :--- | :--- |
| **Prénom / Profil** | Marc, Lead Developer Freelance ou Senior en Startup. |
| **Âge** | 30 - 40 ans. |
| **Localisation** | Télétravail / Paris (Cergy-La Défense via le RER A). |
| **Situation pro** | Consultant indépendant ou Responsable technique. |
| **Niveau d'études** | Ingénieur ou autodidacte avec 10+ ans d'expérience. |
| **Revenus** | 6 000 € - 8 000 € (TJM élevé). |
| **Technologies** | Go, Rust, Cloud Native, Architecture Microservices. |

### 2. Description du Persona
Marc est un expert qui aime transmettre mais manque de temps. Il cherche à diversifier ses activités (mentoring, formation) sans y consacrer 100% de son temps. Il est sensible à la qualité logicielle et désolé de voir autant de "code spaghetti". Il cherche une plateforme pour valoriser son expertise et peut-être sourcer des futurs talents.

### 3. Psychographie
| Attribut | Analyse |
| :--- | :--- |
| **Motivations** | Transmission ; reconnaissance par ses pairs ; veille inversée. |
| **Aspirations** | Créer un impact sur la communauté ; devenir une référence dans son domaine. |
| **Valeurs** : | Code propre ; efficacité ; honnêteté intellectuelle ; pragmatisme métier. |
| **Craintes** | Perdre son temps avec des outils mal conçus ; stagnation personnelle. |
| **Intérêts** | Podcasts Tech ; open-source ; investissement ; domotique. |

### 4. Comportements d'achat
| Vecteur | Description |
| :--- | :--- |
| **Canaux** | X (Twitter) ; Newsletters spécialisées ; Slack/Discord de niches Tech. |
| **Décision** | Valeur du réseau ; qualité technique de l'outil ; respect de la vie privée. |
| **Habitudes** | Prêt à payer pour un outil "Pro" qui lui fait gagner du temps ou de la visibilité. |
| **Prix** | Sensibilité nulle si l'outil apporte un ROI (visibilité ou accès talents). |
| **Influenceurs** | Martin Fowler, Uncle Bob ; leaders d'opinion sur X/LinkedIn. |

### 5. Problématiques clés
1. **Transmission asynchrone** : "Comment aider des jeunes sans bloquer 2h de ma journée ?"
2. **Sourcing de talents** : "Où voir le raisonnement logique réel d'un candidat avant l'entretien ?"
3. **Veille technique** : "Quelles sont les nouvelles manières d'aborder les frameworks récents chez les jeunes ?"
4. **Valorisation d'expertise** : "Comment prouver ma capacité de mentoring pour mes futures missions ?"
5. **Qualité globale** : "Comment contribuer à l'élévation du niveau moyen de code dans l'écosystème ?"

### 6. Arguments clés
- **Personal Branding** : Affirmez votre position d'expert en accumulant des revues certifiées et appréciées.
- **Sourcing prédictif** : Identifiez les pépites techniques en observant leur manière de penser dès l'école.
- **Engagement asynchrone** : Transmettez votre savoir à votre rythme, entre deux sprints.
- **Accès à la relève** : Restez connecté aux nouvelles générations et à leurs usages des frameworks modernes.
- **Impact communautaire** : Participez activement à l'éradication de la dette technique dès la source.

### 7. Scénario d'usage prioritaire : "Chasseur de tête technique"
*   **Besoin Principal** : Identifier un stagiaire ou un junior brillant à Cergy sans passer par des tests algorithmiques génériques.
*   **Besoin Secondaire** : Entretenir ses capacités de mentorat pour justifier une augmentation de TJM.
*   **Déroulement** : Marc passe 15 minutes sur la plateforme entre deux réunions. Il tombe sur le code de Lucas. Impressionné par sa curiosité sur l'architecture, il lui laisse un feedback constructif et l'invite à prendre un café à La Défense.
